# 2026-11-11

## 修复：工具调用被当普通文本输出、回答中断

现象：工作模式跑项目时，模型把 `{"tool":"files","args":{...}}` 裸 JSON 直接吐在正文里，工具不执行、回答原地结束。

根因：项目的工具协议要求模型把调用写在 ` ```tool ` 围栏里（`src/services/tools/protocol.js` 的 `CODE_FENCE_RE` 只认围栏）。`extractToolCalls()` 返回空 → `replyEngine.js` 的 `while` 循环 `if (!calls.length) break` → 不执行工具、不回灌、不发起下一轮 → `fullContent` 原样落到 `msg.content` 被 MarkdownRenderer 当正文渲染。`api.js` 也从不读 `finish_reason`，截断无法感知。

修复（7 个文件）：
- `protocol.js`：新增 `fenceRegions` + `findJsonEnd` 括号配对扫描，`collectBareCallBlocks` 兜底识别裸 JSON 工具调用（含同行多个、跨行断裂、重复键、未闭合 tool 围栏）；`removeByRange` 按位置剥离，确保 calls/removable 同源；新增导出 `stripIncompleteToolCalls`；`buildToolPrompt` 增加输出格式强约束。
- `tools.js`：导出 `stripIncompleteToolCalls`。
- `api.js`：读取 `choices[0].finish_reason`，挂在返回的 usage 上（不新造 chunk 类型，避免其它调用方的 `onChunk({text})` 拼进 undefined）；Ollama 的 `done_reason` 同理。
- `replyEngine.js`：收尾调用 `stripIncompleteToolCalls`，`finish_reason=length` 时给出截断提示。
- 新增回归测试：裸 JSON 多调用/跨行断裂、示例不误执行、流式隐藏、未闭合围栏回收、finish_reason 提示、端到端「不中断继续执行」。

验证：`vitest run` 894/894 通过（38 文件）；`playwright e2e/streamTimeline.spec.js` 3/3 通过；eslint 无告警；`vite build` 成功。

约定：工具调用解析的兜底逻辑集中在 `src/services/tools/protocol.js`，调用执行循环在 `src/services/chat/replyEngine.js`；不要把解析分散到渲染层。
